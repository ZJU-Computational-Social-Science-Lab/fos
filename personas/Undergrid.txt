LVM is a system of partitioning disks to allow for easy management later (there's a whole bunch of benefits but I won't go into them here).  It's made up of PV's (physical volumes, i.e. disks)which contain VG's (volume groups) which in turn contain LV's (Logical volumes).

&amp;#x200B;

In this case, /dev/sda3 is a PV which is filled by the "pve" VGS.  That in turn contains the logical volumes "data", "root" and "swap".  You can think of the later two as partitions, formatted and used as you would expect.

&amp;#x200B;

The "data" LV is a thin volume where volumes will be created when you create VM's or containers (your given the option to use local-lvm during creation).  Right now it's showing 0% used (the Data% column), so that's where your free space is (apart from the free space in your / partition).

> **[r/Proxmox]** Note: You don't say if you have individual addresses or a subnet for your VM's.  Subnets will not work with bridged networking on hetzner, you must use routed mode if you have bought a subnet. Try this:

&amp;#x200B;

    auto lo
    iface lo inet loopback

            up route add -net 144.xxx.xxx.64 netmask 255.255.255.224 gw 144.xxx.xxx.65 dev enp2s0

    iface vmbr0 inet static
            address  144.xxx.xxx.70

            gateway  144.xxx.xxx.65
            bridge_ports enp2s0
            bridge_stp off
            bridge_fd 0

            address  2a01:xxx:xxx:1245::2
            netmask  64
            gateway  fe80::1

> **[r/Proxmox]** OK, so you havn't yet ordered additional IPv4 address.  If you intend to access VM's hosted on your proxmox install via IPv4, you will need additional IPv4 address, at least one for each intended VM (unless your going to use NAT, but that brings a whole heap of other issues).  If you are happy (and able) to only use IPv6, you don't need additional addresses since you already have an IPv6 /64 subnet.

&amp;#x200B;

If you need to buy IPv4 address, click the "Order additional IPs / Nets" button that should be just under the area you screenshotted.  You will see 5 choices (with appropriate prices which I've removed):

* **One additional IP with costs**
* **One failover IP**
* **One additional subnet /29**
* **One additional subnet /28**
* **One additional subnet /27**

&amp;#x200B;

The first option will give you a single IPv4 address suitable for using with bridged networking.  You can order up to 6 of those per server, but you have to order one at a time.  [This Hetzner Wiki page](https://wiki.hetzner.de/index.php/Virtualisierung/en) gives instructions for generating the required MAC addresses and just put the value in the appropriate place in the VM or container creation wizard.

The bottom three options gives you a subnet of the specified size.  A /29 gives 6 usuable address, a /28 gives 14 usable addresses and a /27 gives 30 usable addresses.  These will NOT work with bridged networking, so the config above will not work for them.  If you decide to go this route, I can help you out with that.

I have no idea how the Failover IP's work with proxmox, I haven't tried them.

&amp;#x200B;

BTW: if your annonomysing a Hetzner IPv6 block, you should blur the last set of numbers before the double colon (the :: ) since that's the cluster that is specific to your subnet.
